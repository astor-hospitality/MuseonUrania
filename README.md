# MuseonUrania / VEDAL Portal

**Русский** · [English](README.en.md)

Публичная версия репозитория для портфолио: сайт, админка, API и AI-ассистент
для производителя медицинского оборудования. Реальные доступы, договоры, акты,
счета, коммерческие условия, ключи облака, SMTP, S3 и YandexGPT не хранятся в
git и передаются заказчику отдельным официальным пакетом.

## Что внутри

VEDAL Portal объединяет публичный сайт и закрытую рабочую зону:

- публичные страницы: главная, о компании, продукция, сервис, производство,
  документы, новости, контакты и политика обработки персональных данных;
- каталог изделий с карточками, SEO-метаданными и медиа из объектного
  хранилища;
- формы заявок и сервисных обращений с сохранением в базе и уведомлениями;
- админка для страниц, продукции, документов, новостей, заявок, клиентов,
  сделок, КП, сотрудников и журнала аудита;
- Ведалина, AI-ассистент сайта: публично отвечает по разрешённым материалам,
  внутри закрытого контура может работать с расширенной базой знаний;
- подготовка к handoff в CRM и интеграции с корпоративным контуром заказчика.

## Стек

| Слой | Технологии |

| Frontend | Next.js 16, React 19, TypeScript, CSS Modules, Vitest, Testing Library |

## Быстрый запуск

Нужен Docker с Compose v2. Java, Node и Maven на хост ставить не требуется:
локальный стек собирается в контейнерах.

```bash
./scripts/up.sh
```

На Windows:

```powershell
.\scripts\up.ps1
```

Скрипт проверит Docker, создаст локальный `backend/.env`, соберёт образы и
дождётся готовности сайта.

| Адрес | Назначение |
| --- | --- |
| `http://localhost:8080` | сайт и единая точка входа |
| `http://localhost:8080/admin/` | админка |
| `http://localhost:8080/swagger-ui.html` | Swagger UI |
| `http://localhost:8180` | Keycloak для локального стека |

Остановить стек без удаления данных:

```bash
docker compose -f backend/compose.yaml --profile app down
```

Полностью пересоздать локальные данные:

```bash
docker compose -f backend/compose.yaml --profile app down -v
```

## Переменные окружения

В репозитории лежат только шаблоны:

- `backend/.env.example`;
- `backend/.env.host.example`;
- `frontend/.env.example`.

Боевые и стендовые `.env` не коммитятся. Они включают доступы к PostgreSQL,
Keycloak, SMTP, S3/Object Storage, YandexGPT и доменным настройкам. Для
заказчика такие файлы собираются в официальный пакет передачи доступов вне
репозитория.

## Разработка

Запуск инфраструктуры без сайта и backend-приложения:

```bash
docker compose -f backend/compose.yaml up -d
```

После этого backend и frontend можно запускать с машины разработчика:

```bash
cd backend && ./mvnw spring-boot:run -pl app
cd frontend && npm install && npm run dev
```

Проверки:

```bash
cd backend && ./mvnw test
cd frontend && npm test
cd frontend && npm run lint
```

## Правила публичного репозитория

В git не должны попадать:

- `.env`, ключи, токены, пароли, дампы баз и приватные сертификаты;
- договоры, акты, счета, реквизиты и коммерческие расчёты;
- черновики писем, подписи, персональные контакты исполнителей;
- клиентские PDF, презентации, исходные медиа и временные `outputs/`;
- документы передачи доступов и рабочие инструкции с адресами закрытых сервисов.

Если такие файлы нужны для сдачи проекта, они хранятся в отдельном официальном
пакете вне репозитория.

## GitHub Releases

Release в GitHub — это зафиксированная версия проекта вокруг git-тега:
например `v1.0.0`. В релизе можно написать, что именно вошло, приложить архивы
или документы и дать ссылку на точное состояние кода. Это не сам деплой, но
релиз удобно использовать как контрольную точку: “вот версия, которую показывали
заказчику” или “вот публичная portfolio-safe версия”.
