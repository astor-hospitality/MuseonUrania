# Предупреждение о недоступности — 8 октября 2026

Причина подтверждена официальным инцидентом Яндекс Cloud №2092 — нарушение электропитания в ru-central1-b. Срок восстановления не обещаем.

`frontend/content/service-notice.ts` включает временное предупреждение на публичных страницах портала. После проверки портала, отправки заявок и Ведалины переключить `active` в `false` и пересобрать фронтенд.

Для новой VM подготовлен `frontend/public/service-status.html`: самостоятельная страница с проверенными контактами из контента сайта, без JavaScript, приложения, БД, внешних шрифтов и изображений. Её можно разместить как `index.html` в корне статического сервера до восстановления портала. На резервной VM не запускать пишущие сервисы поверх старой БД без отдельного решения о переключении.

Если прокси отдаёт заглушку вместо приложения, использовать HTTP 503, `Retry-After: 3600` и `Cache-Control: no-store`. Не ставить постоянный редирект, не менять MX и не обещать час восстановления: Retry-After означает время следующей проверки клиентом.

Телефон: 8 800 600 3449. Почта: sales@vedal-med.ru. Статус провайдера: https://status.yandex.cloud/ru/incidents/2092.

На момент подготовки основной домен vedal-med.ru не отвечал по HTTPS. Наличие баннера в коде не означает публикацию на недоступной VM.

## Резервная публикация

Предупреждение опубликовано независимо от Яндекс Cloud: https://astor-hospitality.github.io/MuseonUrania/.

GitHub Pages собирается из отдельной ветки `codex/vedal-status-page`, содержащей только `index.html` и `.nojekyll`. Проверены успешная сборка Pages и публичный HTTP 200. Основной домен и DNS не переключались; по резервной ссылке работает только предупреждение, а не портал, формы или Ведалина.

При переносе на Cloud.ru или VM в Сбере использовать `frontend/public/service-status.html`. После восстановления основного сервиса обновить резервную страницу: убрать предупреждение об аварии и дать ссылку на проверенный работающий портал.
